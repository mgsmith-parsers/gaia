## Обзор

`GaiaBuilder` — обратная сторона [`GaiaParser`](GaiaParser-Russian.md): он превращает набор пар идентификатор применения (AI) / значение в правильно сформированную **строку элементов** GS1 либо **URI GS1 Digital Link**. Вы предоставляете идентификаторы AI и их полные значения данных; построитель их собирает, проверяет результат тем же механизмом, которым пользуется `GaiaParser`, и выдаёт готовый результат.

Поскольку построитель проверяет результат, *разбирая собственный вариант вывода*, всё, что он возвращает, гарантированно читается обратно через `GaiaParser` без ошибок — эти двое никогда не разойдутся в том, что считать правильно сформированным.

**Класс точки входа:** `tools.pantheum.gaia.GaiaBuilder`

## О GS1 и документе General Specifications

**GS1** — международная некоммерческая организация, которая разрабатывает и поддерживает открытые стандарты идентификации и обмена данными в цепях поставок. Её стандарты применяются в розничной торговле, здравоохранении, логистике, общественном питании и многих других отраслях — от штриховых кодов на потребительской упаковке до сериализованного отслеживания фармацевтических доз.

Авторитетным источником для всего, что реализует этот построитель, служит документ **GS1 General Specifications** — единый документ, который определяет:

- Все коды идентификаторов применения (AI), их наименования данных, форматы и правила проверки
- Правила синтаксиса для составления и кодирования строк элементов AI
- Требования к символикам штриховых кодов и назначение идентификаторов символики AIM
- Алгоритмы контрольной цифры и контрольного знака
- Раскрытие двузначного обозначения года (правило скользящего окна)
- Спецификации Data Matrix, QR Code, GS1-128, GS1 DataBar и прочих носителей данных

Документ GS1 General Specifications обновляется ежегодно. Действующая редакция и сопутствующие материалы доступны по адресу:

> **[https://www.gs1.org/standards/gs1-general-specifications](https://www.gs1.org/standards/gs1-general-specifications)**

GAIA реализует **выпуск 26.0 (утверждён в январе 2026 года)** документа GS1 General Specifications.

URI GS1 Digital Link подчиняются отдельному стандарту **GS1 Digital Link: URI Syntax**, который определяет первичные ключи идентификации, порядок квалификаторов ключа и кодирование атрибутов данных, применяемые построителем при выдаче URI Digital Link:

> **[https://ref.gs1.org/standards/digital-link/uri-syntax/](https://ref.gs1.org/standards/digital-link/uri-syntax/)**

GAIA реализует **выпуск 1.7.0 (утверждён в августе 2026 года)** стандарта GS1 Digital Link: URI Syntax.

Ссылки на разделы во всём настоящем документе относятся к GS1 General Specifications (например, «Table 7-5», «section 7.12»), за исключением номеров разделов Digital Link (например, «§4.9», «§4.12»), которые отсылают к стандарту GS1 Digital Link: URI Syntax.

## Быстрый старт

```java
import tools.pantheum.gaia.GaiaBuilder;

// Element string
String es = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .ai("10", "LOT-ABC")
        .ai("17", "271231")
        .buildElementString();
// 0109506000134352 10 LOT-ABC <GS> 17 271231   (GS = FNC1 group separator, 0x1D)

// GS1 Digital Link URI (canonical, on https://id.gs1.org)
String dl = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .ai("10", "LOT-ABC")
        .ai("17", "271231")
        .buildDigitalLinkUri();
// https://id.gs1.org/01/09506000134352/10/LOT-ABC?17=271231
```

Предпочитайте константы `GS1Constants_AICodes` необработанным строкам AI (см. [приложение A руководства по анализатору](GaiaParser-Russian.md#приложение-a--строковые-константы-ai)):

```java
import static tools.pantheum.gaia.gs1.constants.GS1Constants_AICodes.*;

String es = GaiaBuilder.create()
        .ai(AI_01_GTIN, "09506000134352")
        .ai(AI_10_BATCH_LOT, "LOT-ABC")
        .buildElementString();
```

## Как это работает

Каждое построение проходит один и тот же путь:

1. **Сборка** — пары AI/значение соединяются в строку-кандидат элементов. После каждого AI, который *требует разделителя* и не является последним элементом, вставляется групповой разделитель FNC1 (`0x1D`). Идентификаторы AI заранее заданной длины (GTIN, даты, меры постоянной длины) разделителя не получают; все прочие получают. (Нераспознанные AI до этого шага не доходят — `ai(...)` сразу их отвергает; см. [Построение строк элементов](#построение-строк-элементов).)
2. **Проверка** — кандидат разбирается в режиме `CONTENT` посредством `GaiaParser`. Каждое значение сверяется с форматом и контрольной цифрой своего AI, а также применяются структурные правила (обязательные или взаимоисключающие сочетания AI). Если разбор недействителен, построение завершается неудачей.
3. **Выдача** —
   - Для строки элементов возвращается `toElementString()` проверенного объекта.
   - Для Digital Link каждому элементу назначается его роль DL (первичный ключ, квалификатор ключа либо атрибут данных), проверяется последовательность квалификаторов ключа, выдаётся URI, после чего этот URI **разбирается повторно, чтобы убедиться, что он читается обратно как действительный Digital Link**, — защитная проверка сборки строки и процентного кодирования. Если такой обход не удаётся, выбрасывается `GaiaBuilderException`.

Это повторяет логику восстановления из `DLSyntaxParser`, поэтому расстановка разделителей и проверка полностью совпадают с тем, чего ожидает анализатор.

## Построение строк элементов

```java
String es = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .buildElementString();
// 0109506000134352
```

- **AI** проверяется сразу: `ai(...)` выбрасывает `IllegalArgumentException`, если это не распознанный идентификатор применения GS1. (Построитель соединяет AI со значением до разбора, поэтому нераспознанный или слишком длинный AI вроде `"99999"` необходимо перехватить здесь — иначе он молча был бы заново разбит на лексемы как другой AI.) **Значение** же проверяется позже, в момент построения.
- Значения должны быть **полными**, включая контрольную цифру, если она есть. Построитель не вычисляет и не добавляет контрольные цифры за вас — см. [Контрольные цифры](#контрольные-цифры).
- Идентификаторы AI выдаются в порядке добавления. Построитель вставляет разделители FNC1 там, где этого требует синтаксис GS1; самостоятельно их добавлять не нужно.
- Построение **вообще без AI** выбрасывает `GaiaBuilderException("No AIs supplied")` с пустым списком `getErrors()` — единственная неудача, не несущая ни одного `GaiaError`.
- AI, значение которого нарушает правило формата или контрольной цифры, приводит к неудаче построения.

### AI-атрибутам нужен их ключ идентификации

Большинство AI — это *атрибуты*, которым GS1 General Specifications предписывают сопровождение ключом идентификации, и построитель за этим следит: он проверяет данные полным этапом синтаксиса, без возможности отказаться. Одна лишь партия или один серийный номер **не** образуют действительной строки элементов:

```java
GaiaBuilder.create().ai("10", "LOT-ABC").buildElementString();
// GaiaBuilderException: Cannot build a well-formed element string: 1 validation error(s)
//   [GE-S005] AI (10) requires 01 OR 02 OR 03 OR 8006 OR 8026 …

GaiaBuilder.create().ai("01", "09506000134352").ai("10", "LOT-ABC").buildElementString();
// 010950600013435210LOT-ABC        — the GTIN satisfies the requirement
```

Ключи идентификации (GTIN `01`, SSCC `00`, GLN `414`, …) и AI внутреннего применения компании (`90`–`99`) вполне законно стоят сами по себе. Всему остальному нужен его спутник.

> `GaiaParser` можно попросить пропустить эту проверку через `ParseConfig.skipRequiresCheck(true)`; `GaiaBuilder` намеренно не предоставляет ничего подобного — он призван выдавать результат, соответствующий стандартам. Чтобы собрать намеренно неполную строку элементов, соедините её самостоятельно и разберите с отключённой проверкой.

## Построение URI Digital Link

```java
// Canonical form (https://id.gs1.org)
String dl = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .ai("21", "SERIAL123")
        .buildDigitalLinkUri();
// https://id.gs1.org/01/09506000134352/21/SERIAL123
```

Действительный Digital Link требует ровно одного **первичного ключа идентификации** (например, GTIN `01`, GLN `414`, SSCC `00`). Построитель распределяет каждый переданный AI:

| Роль | Выдаётся как | Пример |
|------|-------------|---------|
| Первичный ключ идентификации | Сегмент пути после домена или префикса | `/01/09506000134352` |
| Квалификатор ключа (CPV `22`, партия `10`, серийный номер `21`, …) | Последующие сегменты пути, в **каноническом порядке из §4.9** (а не в порядке добавления) | `/10/LOT-ABC` |
| Атрибут данных (всё остальное) | Параметры запроса, **отсортированные лексикографически по ключу AI** (§4.12) | `?17=271231` |

Поскольку при выдаче квалификаторы переупорядочиваются, передавать их вразнобой не составляет проблемы: `ai("21", …)` перед `ai("10", …)` всё равно даст `/10/LOT/21/SER`. Допустимым для первичного ключа должен быть лишь сам *набор*.

Значения кодируются процентами и в пути, и в запросе.

Построение **завершается неудачей** (выбрасывает `GaiaBuilderException` либо возвращает неуспешный `BuildResult`), когда:

- среди идентификаторов AI **нет** первичного ключа идентификации;
- первичных ключей идентификации **больше одного**;
- какой-либо AI **запрещён** в Digital Link (`03`, `8014`);
- **последовательность квалификаторов ключа** недопустима для выбранного первичного ключа (например, квалификатор, не относящийся к этому ключу, либо квалификаторы вне разрешённого порядка).

## BuilderDigitalLinkConfig

Передайте `BuilderDigitalLinkConfig`, чтобы управлять схемой, доменом, префиксом пути, дополнительными параметрами запроса и фрагментом:

```java
import tools.pantheum.gaia.config.BuilderDigitalLinkConfig;

BuilderDigitalLinkConfig cfg = BuilderDigitalLinkConfig.builder()
        .baseUrl("https://example.com/resolver")   // sets scheme, domain, and path prefix at once
        .addQueryParam("context", "retail")        // appended after the AI data attributes
        .fragment("section-2")
        .build();

String dl = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .buildDigitalLinkUri(cfg);
// https://example.com/resolver/01/09506000134352?context=retail#section-2
```

| Метод построителя | Назначение | По умолчанию |
|----------------|---------|---------|
| `scheme(String)` | Схема URI; должна быть `http` либо `https` | `https` |
| `domain(String)` | Полномочие — узел либо `узел:порт` | `id.gs1.org` |
| `pathPrefix(String)` | Сегменты пути перед первым первичным ключом; ведущие и завершающие косые черты нормализуются | *(нет)* |
| `baseUrl(String)` | Сокращение, разбивающее URL на `scheme` + `domain` + `pathPrefix` | — |
| `addQueryParam(String, String)` | Дополнительный параметр запроса, добавляемый **после** атрибутов данных AI, в порядке вставки; кодируется процентами | — |
| `fragment(String)` | Фрагмент URL (без ведущего `#`); кодируется процентами | *(нет)* |

`build()` проверяет настройки сразу: схема, отличная от `http(s)`, либо пустой домен выбрасывают `IllegalArgumentException`.

- `BuilderDigitalLinkConfig.canonical()` (псевдоним `defaultConfig()`) — значение по умолчанию `https://id.gs1.org` без дополнений: ровно то, что использует `buildDigitalLinkUri()` без аргументов и что выдаёт `GS1AIObject.getCanonicalDigitalLink()`.
- `baseUrl("http://id.example.org:8080/r")` → схема `http`, домен `id.example.org:8080`, префикс пути `/r`.
- Дополнительные параметры запроса всегда следуют за атрибутами, полученными из AI, благодаря чему сохраняется канонический порядок AI (§4.12).

`BuilderDigitalLinkConfig` неизменяем; один экземпляр можно свободно использовать многократно.

## Проверка и ошибки

### Методы построения, выбрасывающие исключения

`buildElementString()`, `buildDigitalLinkUri()` и `buildDigitalLinkUri(BuilderDigitalLinkConfig)` выбрасывают **`GaiaBuilderException`** (непроверяемое `RuntimeException`), когда из идентификаторов AI не удаётся получить правильно сформированный результат:

```java
try {
    String es = GaiaBuilder.create().ai("01", "09506000134350").buildElementString();
} catch (GaiaBuilderException ex) {
    System.err.println(ex.getMessage());     // human-readable summary
    ex.getErrors().forEach(System.err::println);  // underlying GaiaError list
}
```

- При сбоях **содержимого** (неверная контрольная цифра, несоответствие формата, отсутствующий либо исключённый AI) `getErrors()` несёт объекты `GaiaError` анализатора — те же самые, что [описаны в руководстве по анализатору](GaiaParser-Russian.md#gaiaerror).
- При **структурных сбоях Digital Link** (нет первичного ключа, более одного первичного ключа, запрещённый AI, недопустимая последовательность квалификаторов ключа) `getErrors()` несёт единственный `GaiaError` (код `GE-L008`, `GE-L012`, `GE-L013` либо `GE-L014`), локализованный на язык построителя.

### Методы tryBuild\* без исключений

Когда ввод поступает от пользователя, а неудача — ожидаемый и поправимый исход, применяйте разновидности `tryBuild*` вместо управления потоком через исключения. Они возвращают [`BuildResult`](#buildresult), а не выбрасывают исключение:

```java
BuildResult r = GaiaBuilder.create()
        .ai("01", userValue)
        .tryBuildElementString();

if (r.isSuccess()) {
    use(r.getValue());
} else {
    report(r.getMessage(), r.getErrors());
}
```

| С исключением | Без исключения |
|----------|--------------|
| `buildElementString()` | `tryBuildElementString()` |
| `buildDigitalLinkUri()` | `tryBuildDigitalLinkUri()` |
| `buildDigitalLinkUri(BuilderDigitalLinkConfig)` | `tryBuildDigitalLinkUri(BuilderDigitalLinkConfig)` |

Каждый метод `tryBuild*` разделяет то же ядро проверки со своим выбрасывающим двойником; различается лишь способ сообщить о неудаче.

### Язык сообщений об ошибках

Ошибки проверки содержимого берутся из локализованного каталога ошибок. Вызовите `language(...)`, чтобы выбрать язык сообщений объектов `GaiaError`, которые несут `GaiaBuilderException.getErrors()` / `BuildResult.getErrors()`; по умолчанию это английский:

```java
BuildResult r = GaiaBuilder.create()
        .language(GaiaConstants.Language.FRENCH)
        .ai("01", userValue)
        .tryBuildElementString();
// r.getErrors() messages are in French
```

Это та же настройка `GaiaConstants.Language`, которую `GaiaParser` принимает через `ParseConfig`, поэтому построитель и анализатор локализуются одинаково.

И сообщения `GaiaError` о **содержимом**, и **структурные сбои Digital Link** (нет первичного ключа, более одного первичного ключа, запрещённый AI, недопустимая последовательность квалификаторов ключа) локализуются через общий каталог ошибок — последние с помощью кодов `GE-L008`, `GE-L012`, `GE-L013` и `GE-L014`.

### BuildResult

`BuildResult` (в пакете `tools.pantheum.gaia.result`) — неизменяемый тип-значение, описывающий исход вызова `tryBuild*`:

| Метод | При успехе | При неудаче |
|--------|------------|------------|
| `isSuccess()` | `true` | `false` |
| `getValue()` | полученная строка | `null` |
| `getMessage()` | `null` | описание неудачи |
| `getErrors()` | пустой список | ошибки проверки (те же, что у `GaiaBuilderException.getErrors()`) |

## Контрольные цифры

Построитель проверяет контрольные цифры, но **не** вычисляет их — значения уже должны содержать свою. Чтобы вычислить контрольную цифру, воспользуйтесь `GS1Utils.calculateCheckDigit`:

```java
import tools.pantheum.gaia.gs1.util.GS1Utils;

int cd = GS1Utils.calculateCheckDigit("0950600013435");  // → 2
String gtin = "0950600013435" + cd;                      // 09506000134352
String es = GaiaBuilder.create().ai("01", gtin).buildElementString();
```

`calculateCheckDigit(String)` применяет стандартный алгоритм GS1 по модулю 10 к переданным цифрам и возвращает контрольную цифру `0–9` либо `-1`, если ввод равен null, пуст либо не является числовым.

## Потокобезопасность

`GaiaBuilder` **не** потокобезопасен и предназначен для однократного применения: вызовите `create()`, добавьте идентификаторы AI, постройте один раз. Создавайте новый построитель для каждого результата; не используйте один совместно в нескольких потоках.

`BuilderDigitalLinkConfig` (и создаваемые им объекты `BuildResult`) неизменяемы, и их можно свободно использовать совместно — постройте конфигурацию один раз при запуске и применяйте её во многих построителях.

## Справочник API

### `GaiaBuilder`

| Метод | Описание |
|--------|-------------|
| `static GaiaBuilder create()` | Начинает новый, пустой построитель. |
| `GaiaBuilder ai(String ai, String value)` | Добавляет AI и его полное значение. Выбрасывает `IllegalArgumentException`, если любой из аргументов равен `null` либо если `ai` не является распознанным идентификатором применения GS1. |
| `GaiaBuilder language(GaiaConstants.Language language)` | Задаёт язык сообщений об ошибках проверки содержимого (по умолчанию английский). `null` пропускается. |
| `String buildElementString()` | Выдаёт строку элементов GS1. При неудаче выбрасывает `GaiaBuilderException`. |
| `String buildDigitalLinkUri()` | Выдаёт канонический URI Digital Link. При неудаче выбрасывает `GaiaBuilderException`. |
| `String buildDigitalLinkUri(BuilderDigitalLinkConfig config)` | Выдаёт URI Digital Link согласно `config`. При неудаче выбрасывает `GaiaBuilderException`. |
| `BuildResult tryBuildElementString()` | Построение строки элементов без исключений. |
| `BuildResult tryBuildDigitalLinkUri()` | Построение канонического Digital Link без исключений. |
| `BuildResult tryBuildDigitalLinkUri(BuilderDigitalLinkConfig config)` | Построение Digital Link согласно `config`, без исключений. |

### `BuilderDigitalLinkConfig`

| Член | Описание |
|--------|-------------|
| `static BuilderDigitalLinkConfig canonical()` / `defaultConfig()` | Значение по умолчанию `https://id.gs1.org`. |
| `static Builder builder()` | Новый построитель конфигурации. |
| `getScheme()` / `getDomain()` / `getPathPrefix()` | Определённые схема, полномочие и префикс пути. |
| `getExtraQueryParams()` | Дополнительные параметры запроса в порядке вставки. |
| `getFragment()` | Фрагмент либо `null`. |

### `GaiaBuilderException`

| Член | Описание |
|--------|-------------|
| `getErrors()` | Объекты `GaiaError`, вызвавшие неудачу, — ошибки анализатора при сбое содержимого либо единственная структурная ошибка Digital Link (`GE-L008`/`GE-L012`/`GE-L013`/`GE-L014`). Никогда не `null`. |

### `BuildResult`

| Член | Описание |
|--------|-------------|
| `isSuccess()` | Удалось ли построение. |
| `getValue()` | Полученный результат при успехе; `null` при неудаче. |
| `getMessage()` | Описание неудачи при неудаче; `null` при успехе. |
| `getErrors()` | Ошибки проверки при неудаче; пустой список при успехе. Никогда не `null`. |
| `getTiming()` | Объект `ProcessingTiming` для построения (время начала, длительность обработки) либо `null`. |
