## Огляд

`GaiaBuilder` — зворотний бік [`GaiaParser`](GaiaParser-Ukrainian.md): він перетворює набір пар ідентифікатор застосування (AI) / значення на правильно сформований **рядок елементів** GS1 або **URI GS1 Digital Link**. Ви надаєте ідентифікатори AI та їхні повні значення даних; будівник їх складає, перевіряє результат тим самим механізмом, яким користується `GaiaParser`, і видає готовий результат.

Оскільки будівник перевіряє результат, *розбираючи власний варіант виводу*, усе, що він повертає, гарантовано читається назад через `GaiaParser` без помилок — ці двоє ніколи не розійдуться в тому, що вважати правильно сформованим.

**Клас точки входу:** `tools.pantheum.gaia.GaiaBuilder`

## Про GS1 і документ General Specifications

**GS1** — міжнародна неприбуткова організація, що розробляє та підтримує відкриті стандарти ідентифікації й обміну даними в ланцюгах постачання. Її стандарти застосовують у роздрібній торгівлі, охороні здоров'я, логістиці, громадському харчуванні та багатьох інших галузях — від штрихових кодів на споживчому пакованні до серіалізованого відстеження фармацевтичних доз.

Авторитетним джерелом для всього, що реалізує цей будівник, є документ **GS1 General Specifications** — єдиний документ, який визначає:

- Усі коди ідентифікаторів застосування (AI), їхні назви даних, формати та правила перевірки
- Правила синтаксису для складання й кодування рядків елементів AI
- Вимоги до символік штрихових кодів і призначення ідентифікаторів символіки AIM
- Алгоритми контрольної цифри та контрольного знака
- Розкриття двоцифрового позначення року (правило рухомого вікна)
- Специфікації Data Matrix, QR Code, GS1-128, GS1 DataBar та інших носіїв даних

Документ GS1 General Specifications оновлюють щороку. Чинна редакція та супровідні матеріали доступні за адресою:

> **[https://www.gs1.org/standards/gs1-general-specifications](https://www.gs1.org/standards/gs1-general-specifications)**

GAIA реалізує **випуск 26.0 (затверджений у січні 2026 року)** документа GS1 General Specifications.

URI GS1 Digital Link підпорядковані окремому стандарту **GS1 Digital Link: URI Syntax**, який визначає первинні ключі ідентифікації, порядок кваліфікаторів ключа та кодування атрибутів даних, що їх будівник застосовує під час видачі URI Digital Link:

> **[https://ref.gs1.org/standards/digital-link/uri-syntax/](https://ref.gs1.org/standards/digital-link/uri-syntax/)**

GAIA реалізує **випуск 1.7.0 (затверджений у серпні 2026 року)** стандарту GS1 Digital Link: URI Syntax.

Посилання на розділи в усьому цьому документі стосуються GS1 General Specifications (наприклад, «Table 7-5», «section 7.12»), окрім номерів розділів Digital Link (наприклад, «§4.9», «§4.12»), які відсилають до стандарту GS1 Digital Link: URI Syntax.

## Швидкий старт

```java
import tools.pantheum.gaia.GaiaBuilder;

// Element string
String es = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .ai("10", "LOT-ABC")
        .ai("17", "271231")
        .buildElementString();
// 0109506000134352 10 LOT-ABC <GS> 17 271231   (GS = FNC1 group separator, 0x1D)

// GS1 Digital Link URI (canonical, on https://id.gs1.org)
String dl = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .ai("10", "LOT-ABC")
        .ai("17", "271231")
        .buildDigitalLinkUri();
// https://id.gs1.org/01/09506000134352/10/LOT-ABC?17=271231
```

Надавайте перевагу сталим `GS1Constants_AICodes` перед необробленими рядками AI (див. [додаток A посібника з аналізатора](GaiaParser-Ukrainian.md#додаток-a--рядкові-сталі-ai)):

```java
import static tools.pantheum.gaia.gs1.constants.GS1Constants_AICodes.*;

String es = GaiaBuilder.create()
        .ai(AI_01_GTIN, "09506000134352")
        .ai(AI_10_BATCH_LOT, "LOT-ABC")
        .buildElementString();
```

## Як це працює

Кожна побудова проходить той самий шлях:

1. **Складання** — пари AI/значення з'єднують у рядок-кандидат елементів. Після кожного AI, який *потребує роздільника* й не є останнім елементом, вставляють груповий роздільник FNC1 (`0x1D`). Ідентифікатори AI наперед заданої довжини (GTIN, дати, міри сталої довжини) роздільника не отримують; усі інші отримують. (Нерозпізнані AI до цього кроку не доходять — `ai(...)` одразу їх відкидає; див. [Побудова рядків елементів](#побудова-рядків-елементів).)
2. **Перевірка** — кандидата розбирають у режимі `CONTENT` за допомогою `GaiaParser`. Кожне значення звіряють із форматом і контрольною цифрою його AI, а також застосовують структурні правила (обов'язкові чи взаємовиключні поєднання AI). Якщо розбір недійсний, побудова зазнає невдачі.
3. **Видача** —
   - Для рядка елементів повертають `toElementString()` перевіреного об'єкта.
   - Для Digital Link кожному елементу призначають його роль DL (первинний ключ, кваліфікатор ключа або атрибут даних), перевіряють послідовність кваліфікаторів ключа, видають URI, після чого цей URI **розбирають повторно, щоб переконатися, що він читається назад як дійсний Digital Link**, — це захисна перевірка складання рядка та відсоткового кодування. Якщо такий обхід не вдається, викидають `GaiaBuilderException`.

Це повторює логіку відновлення з `DLSyntaxParser`, тож розставлення роздільників і перевірка цілком збігаються з тим, чого очікує аналізатор.

## Побудова рядків елементів

```java
String es = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .buildElementString();
// 0109506000134352
```

- **AI** перевіряють одразу: `ai(...)` викидає `IllegalArgumentException`, якщо це не розпізнаний ідентифікатор застосування GS1. (Будівник з'єднує AI зі значенням до розбору, тож нерозпізнаний або надто довгий AI на кшталт `"99999"` потрібно перехопити тут — інакше його мовчки розбили б на лексеми заново як інший AI.) **Значення** ж перевіряють пізніше, під час побудови.
- Значення мають бути **повними**, зокрема з контрольною цифрою, якщо вона є. Будівник не обчислює й не додає контрольних цифр за вас — див. [Контрольні цифри](#контрольні-цифри).
- Ідентифікатори AI видають у порядку додавання. Будівник вставляє роздільники FNC1 там, де цього вимагає синтаксис GS1; самостійно їх додавати не потрібно.
- Побудова **взагалі без AI** викидає `GaiaBuilderException("No AIs supplied")` із порожнім списком `getErrors()` — єдина невдача, що не несе жодного `GaiaError`.
- AI, значення якого порушує правило формату чи контрольної цифри, призводить до невдачі побудови.

### AI-атрибутам потрібен їхній ключ ідентифікації

Більшість AI — це *атрибути*, яким GS1 General Specifications приписують супровід ключем ідентифікації, і будівник цього дотримується: він перевіряє дані повним етапом синтаксису, без можливості відмовитися. Сама лише партія чи сам серійний номер **не** утворюють дійсного рядка елементів:

```java
GaiaBuilder.create().ai("10", "LOT-ABC").buildElementString();
// GaiaBuilderException: Cannot build a well-formed element string: 1 validation error(s)
//   [GE-S005] AI (10) requires 01 OR 02 OR 03 OR 8006 OR 8026 …

GaiaBuilder.create().ai("01", "09506000134352").ai("10", "LOT-ABC").buildElementString();
// 010950600013435210LOT-ABC        — the GTIN satisfies the requirement
```

Ключі ідентифікації (GTIN `01`, SSCC `00`, GLN `414`, …) та AI внутрішнього застосування компанії (`90`–`99`) цілком законно стоять окремо. Усьому іншому потрібен його супутник.

> `GaiaParser` можна попросити пропустити цю перевірку через `ParseConfig.skipRequiresCheck(true)`; `GaiaBuilder` навмисно не надає нічого подібного — він покликаний видавати результат, що відповідає стандартам. Щоб скласти навмисно неповний рядок елементів, з'єднайте його самостійно й розберіть із вимкненою перевіркою.

## Побудова URI Digital Link

```java
// Canonical form (https://id.gs1.org)
String dl = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .ai("21", "SERIAL123")
        .buildDigitalLinkUri();
// https://id.gs1.org/01/09506000134352/21/SERIAL123
```

Дійсний Digital Link потребує рівно одного **первинного ключа ідентифікації** (наприклад, GTIN `01`, GLN `414`, SSCC `00`). Будівник розподіляє кожен переданий AI:

| Роль | Видається як | Приклад |
|------|-------------|---------|
| Первинний ключ ідентифікації | Сегмент шляху після домену чи префікса | `/01/09506000134352` |
| Кваліфікатор ключа (CPV `22`, партія `10`, серійний номер `21`, …) | Подальші сегменти шляху, у **канонічному порядку з §4.9** (а не в порядку додавання) | `/10/LOT-ABC` |
| Атрибут даних (усе інше) | Параметри запиту, **упорядковані лексикографічно за ключем AI** (§4.12) | `?17=271231` |

Оскільки під час видачі кваліфікатори переупорядковують, передавати їх урозсип не становить проблеми: `ai("21", …)` перед `ai("10", …)` усе одно дасть `/10/LOT/21/SER`. Дозволеним для первинного ключа має бути лише сам *набір*.

Значення кодують відсотками і в шляху, і в запиті.

Побудова **зазнає невдачі** (викидає `GaiaBuilderException` або повертає невдалий `BuildResult`), коли:

- серед ідентифікаторів AI **немає** первинного ключа ідентифікації;
- первинних ключів ідентифікації **більше ніж один**;
- якийсь AI **заборонено** в Digital Link (`03`, `8014`);
- **послідовність кваліфікаторів ключа** недопустима для обраного первинного ключа (наприклад, кваліфікатор, що не належить до цього ключа, або кваліфікатори поза дозволеним порядком).

## BuilderDigitalLinkConfig

Передайте `BuilderDigitalLinkConfig`, щоб керувати схемою, доменом, префіксом шляху, додатковими параметрами запиту та фрагментом:

```java
import tools.pantheum.gaia.config.BuilderDigitalLinkConfig;

BuilderDigitalLinkConfig cfg = BuilderDigitalLinkConfig.builder()
        .baseUrl("https://example.com/resolver")   // sets scheme, domain, and path prefix at once
        .addQueryParam("context", "retail")        // appended after the AI data attributes
        .fragment("section-2")
        .build();

String dl = GaiaBuilder.create()
        .ai("01", "09506000134352")
        .buildDigitalLinkUri(cfg);
// https://example.com/resolver/01/09506000134352?context=retail#section-2
```

| Метод будівника | Призначення | Типово |
|----------------|---------|---------|
| `scheme(String)` | Схема URI; має бути `http` або `https` | `https` |
| `domain(String)` | Повноваження — вузол або `вузол:порт` | `id.gs1.org` |
| `pathPrefix(String)` | Сегменти шляху перед першим первинним ключем; провідні та кінцеві скісні риски нормалізують | *(немає)* |
| `baseUrl(String)` | Скорочення, що розкладає URL на `scheme` + `domain` + `pathPrefix` | — |
| `addQueryParam(String, String)` | Додатковий параметр запиту, який додають **після** атрибутів даних AI, у порядку вставляння; кодують відсотками | — |
| `fragment(String)` | Фрагмент URL (без провідного `#`); кодують відсотками | *(немає)* |

`build()` перевіряє налаштування одразу: схема, відмінна від `http(s)`, або порожній домен викидають `IllegalArgumentException`.

- `BuilderDigitalLinkConfig.canonical()` (псевдонім `defaultConfig()`) — типове значення `https://id.gs1.org` без доповнень: саме те, що використовує `buildDigitalLinkUri()` без аргументів і що видає `GS1AIObject.getCanonicalDigitalLink()`.
- `baseUrl("http://id.example.org:8080/r")` → схема `http`, домен `id.example.org:8080`, префікс шляху `/r`.
- Додаткові параметри запиту завжди йдуть після атрибутів, одержаних з AI, завдяки чому зберігається канонічний порядок AI (§4.12).

`BuilderDigitalLinkConfig` незмінний; один примірник можна вільно використовувати багаторазово.

## Перевірка та помилки

### Методи побудови, що викидають винятки

`buildElementString()`, `buildDigitalLinkUri()` і `buildDigitalLinkUri(BuilderDigitalLinkConfig)` викидають **`GaiaBuilderException`** (неперевірюваний `RuntimeException`), коли з ідентифікаторів AI не вдається одержати правильно сформований результат:

```java
try {
    String es = GaiaBuilder.create().ai("01", "09506000134350").buildElementString();
} catch (GaiaBuilderException ex) {
    System.err.println(ex.getMessage());     // human-readable summary
    ex.getErrors().forEach(System.err::println);  // underlying GaiaError list
}
```

- За збоїв **вмісту** (хибна контрольна цифра, невідповідність формату, відсутній чи виключений AI) `getErrors()` несе об'єкти `GaiaError` аналізатора — ті самі, що [описані в посібнику з аналізатора](GaiaParser-Ukrainian.md#gaiaerror).
- За **структурних збоїв Digital Link** (немає первинного ключа, більше ніж один первинний ключ, заборонений AI, недопустима послідовність кваліфікаторів ключа) `getErrors()` несе єдиний `GaiaError` (код `GE-L008`, `GE-L012`, `GE-L013` або `GE-L014`), локалізований мовою будівника.

### Методи tryBuild\* без винятків

Коли введення надходить від користувача, а невдача — очікуваний і виправний результат, застосовуйте різновиди `tryBuild*` замість керування потоком через винятки. Вони повертають [`BuildResult`](#buildresult), а не викидають виняток:

```java
BuildResult r = GaiaBuilder.create()
        .ai("01", userValue)
        .tryBuildElementString();

if (r.isSuccess()) {
    use(r.getValue());
} else {
    report(r.getMessage(), r.getErrors());
}
```

| З винятком | Без винятку |
|----------|--------------|
| `buildElementString()` | `tryBuildElementString()` |
| `buildDigitalLinkUri()` | `tryBuildDigitalLinkUri()` |
| `buildDigitalLinkUri(BuilderDigitalLinkConfig)` | `tryBuildDigitalLinkUri(BuilderDigitalLinkConfig)` |

Кожен метод `tryBuild*` має те саме ядро перевірки, що і його двійник, який викидає винятки; різниться лише спосіб повідомити про невдачу.

### Мова повідомлень про помилки

Помилки перевірки вмісту беруть із локалізованого каталогу помилок. Викличте `language(...)`, щоб обрати мову повідомлень об'єктів `GaiaError`, які несуть `GaiaBuilderException.getErrors()` / `BuildResult.getErrors()`; типово це англійська:

```java
BuildResult r = GaiaBuilder.create()
        .language(GaiaConstants.Language.FRENCH)
        .ai("01", userValue)
        .tryBuildElementString();
// r.getErrors() messages are in French
```

Це те саме налаштування `GaiaConstants.Language`, яке `GaiaParser` приймає через `ParseConfig`, тож будівник і аналізатор локалізуються однаково.

І повідомлення `GaiaError` про **вміст**, і **структурні збої Digital Link** (немає первинного ключа, більше ніж один первинний ключ, заборонений AI, недопустима послідовність кваліфікаторів ключа) локалізують через спільний каталог помилок — останні за допомогою кодів `GE-L008`, `GE-L012`, `GE-L013` та `GE-L014`.

### BuildResult

`BuildResult` (у пакеті `tools.pantheum.gaia.result`) — незмінний тип-значення, що описує результат виклику `tryBuild*`:

| Метод | За успіху | За невдачі |
|--------|------------|------------|
| `isSuccess()` | `true` | `false` |
| `getValue()` | одержаний рядок | `null` |
| `getMessage()` | `null` | опис невдачі |
| `getErrors()` | порожній список | помилки перевірки (ті самі, що в `GaiaBuilderException.getErrors()`) |

## Контрольні цифри

Будівник перевіряє контрольні цифри, але **не** обчислює їх — значення вже мають містити свою. Щоб обчислити контрольну цифру, скористайтеся `GS1Utils.calculateCheckDigit`:

```java
import tools.pantheum.gaia.gs1.util.GS1Utils;

int cd = GS1Utils.calculateCheckDigit("0950600013435");  // → 2
String gtin = "0950600013435" + cd;                      // 09506000134352
String es = GaiaBuilder.create().ai("01", gtin).buildElementString();
```

`calculateCheckDigit(String)` застосовує стандартний алгоритм GS1 за модулем 10 до переданих цифр і повертає контрольну цифру `0–9` або `-1`, якщо введення дорівнює null, порожнє чи не є числовим.

## Потокобезпечність

`GaiaBuilder` **не** потокобезпечний і призначений для одноразового застосування: викличте `create()`, додайте ідентифікатори AI, побудуйте один раз. Створюйте новий будівник для кожного результату; не використовуйте один спільно в кількох потоках.

`BuilderDigitalLinkConfig` (та створювані ним об'єкти `BuildResult`) незмінні, і їх можна вільно використовувати спільно — побудуйте конфігурацію один раз під час запуску й застосовуйте її в багатьох будівниках.

## Довідник API

### `GaiaBuilder`

| Метод | Опис |
|--------|-------------|
| `static GaiaBuilder create()` | Розпочинає новий, порожній будівник. |
| `GaiaBuilder ai(String ai, String value)` | Додає AI та його повне значення. Викидає `IllegalArgumentException`, якщо будь-який з аргументів дорівнює `null` або якщо `ai` не є розпізнаним ідентифікатором застосування GS1. |
| `GaiaBuilder language(GaiaConstants.Language language)` | Задає мову повідомлень про помилки перевірки вмісту (типово англійська). `null` пропускають. |
| `String buildElementString()` | Видає рядок елементів GS1. За невдачі викидає `GaiaBuilderException`. |
| `String buildDigitalLinkUri()` | Видає канонічний URI Digital Link. За невдачі викидає `GaiaBuilderException`. |
| `String buildDigitalLinkUri(BuilderDigitalLinkConfig config)` | Видає URI Digital Link згідно з `config`. За невдачі викидає `GaiaBuilderException`. |
| `BuildResult tryBuildElementString()` | Побудова рядка елементів без винятків. |
| `BuildResult tryBuildDigitalLinkUri()` | Побудова канонічного Digital Link без винятків. |
| `BuildResult tryBuildDigitalLinkUri(BuilderDigitalLinkConfig config)` | Побудова Digital Link згідно з `config`, без винятків. |

### `BuilderDigitalLinkConfig`

| Член | Опис |
|--------|-------------|
| `static BuilderDigitalLinkConfig canonical()` / `defaultConfig()` | Типове значення `https://id.gs1.org`. |
| `static Builder builder()` | Новий будівник конфігурації. |
| `getScheme()` / `getDomain()` / `getPathPrefix()` | Визначені схема, повноваження та префікс шляху. |
| `getExtraQueryParams()` | Додаткові параметри запиту в порядку вставляння. |
| `getFragment()` | Фрагмент або `null`. |

### `GaiaBuilderException`

| Член | Опис |
|--------|-------------|
| `getErrors()` | Об'єкти `GaiaError`, що спричинили невдачу, — помилки аналізатора за збою вмісту або єдина структурна помилка Digital Link (`GE-L008`/`GE-L012`/`GE-L013`/`GE-L014`). Ніколи не `null`. |

### `BuildResult`

| Член | Опис |
|--------|-------------|
| `isSuccess()` | Чи вдалася побудова. |
| `getValue()` | Одержаний результат за успіху; `null` за невдачі. |
| `getMessage()` | Опис невдачі за невдачі; `null` за успіху. |
| `getErrors()` | Помилки перевірки за невдачі; порожній список за успіху. Ніколи не `null`. |
| `getTiming()` | Об'єкт `ProcessingTiming` для побудови (час початку, тривалість обробки) або `null`. |
